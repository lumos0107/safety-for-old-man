# 평가·보완 반복 기록

작성 2026-09-30 · 팀 눈길손길

얼굴 윤곽 기능까지 구현한 뒤, **평가 에이전트로 평가 → 보완점 반영 → 재검증**을 3번 반복했다. 각 버전에서 무엇이 달라졌는지 적는다.

- 평가 에이전트: 매 회차 같은 지시문 `design/eval/evaluator.md`를 쓰는 새 에이전트(이전 대화를 모름). 테스트·브라우저 종단 검증을 직접 실행하고 7개 기준(동작·안정성·보안·사생활·사용성·코드 품질·테스트·문서)을 1~5점으로 매기고 보완점을 필수/권장/선택으로 낸다.
- 반영 원칙: **필수는 모두**, 권장·선택은 효과를 따져 반영한다. 코드 변경은 실패하는 테스트를 먼저 만들고 통과시킨다. 반영하지 않은 항목은 이유를 남긴다.

## v1 → v2 (1회차 평가 반영)

### 평가 요약 (v1)
- 실행 점검: 서버 60·Node 25·종단 16단계 모두 통과, 스크린샷에서 뼈대·윤곽이 정확히 겹침. 직전 코드 검토 반영 6건 확인.
- 평가자가 **직접 재현한 결함 1건(필수)**: 실행 중 "카메라 전환"을 누르고 새 카메라가 열리기 전에 "정지"를 누르면, 정지 상태인데 카메라가 켜진 채 영상이 계속 나온다.

### 반영한 것
| 등급 | 보완점 | 무엇을 바꿨나 | 검증 |
|---|---|---|---|
| 필수 | 전환 직후 정지하면 카메라가 꺼지지 않음 | `stop()`이 진행 중인 카메라 요청을 무효화 (`cameraRequest++`) | 종단 "카메라 전환 직후 정지해도 카메라가 꺼짐" — 수정을 빼면 "트랙 1개 살아 있음"으로 실패함을 확인 |
| 권장 | 얼굴 탐지 거리 한계가 화면에 안 보임 | 얼굴이 3초 넘게 안 잡히면 "화면 폭의 1/5 이상 되도록 가까이" 안내, 잡히면 지움 | 종단: 멀리 있는 얼굴 영상에서 안내, 가까운 얼굴에서는 안내 없음 |
| 권장 | 개발 경위 문서가 구현 전 상태 | 5장 테스트 범위, 7장 남은 일(실기기 확인)로 갱신 | — |
| 권장 | 일부 종단 페이지가 오류를 수집하지 않음 | 모델 실패 페이지·먼 얼굴 페이지에도 콘솔 오류·CSP 위반 수집 (일부러 막은 요청의 실패만 예상된 오류로 분리) | 종단 |
| 권장 | "얼굴 좌표는 서버로 안 감"을 검증하는 테스트 없음 | 종단에서 서버로 간 텍스트 메시지를 모두 기록해 `auth`·`{type:frame, seq}` 모양만 있는지 확인 | 종단 "서버로 간 메시지에 얼굴 정보 없음" |
| 권장 | 토큰이 계정 공용 출처의 저장소에 있음 | README에 운영 원칙: "이 계정에는 다른 Pages 사이트를 두지 않는다" (코드는 유지 — 아래) | — |
| 선택 | 390px에서 버튼 글자가 단어 중간에서 줄바꿈 | 버튼에 `word-break: keep-all` | 스크린샷 |
| 선택 | 프레임 오류가 영어 코드 그대로 | `frameErrorText`로 한국어 안내 | Node |
| 선택 | 동기 표시 중에도 "동기로 바꾸세요" 안내 | 표시 방식에 따라 안내 문구를 바꿈 | 종단 |
| 선택 | 설정 창이 열린 채 얼굴 모델 오류가 나면 체크박스가 켬으로 남음 | 오류 때 열린 체크박스도 끔 | 종단 "설정 창을 연 채로 실패" |
| 선택 | 설계는 `faceOutline`을 주 함수로 설명 | 설계를 실제 구조(`pickOutline`·`outlineToCanvas`)로 고침 | — |

### 반영하지 않은 것
| 등급 | 보완점 | 이유 |
|---|---|---|
| 권장 | 토큰을 `sessionStorage`에 두는 선택지 | 설계 검토에서 이미 받아들인 위험(본인 계정). 운영 원칙을 문서로 두는 것으로 대신. 다른 Pages를 두게 되면 다시 판단 |
| 권장 | 아이폰에서 카메라 트랙이 끝나면(`ended`) 다시 열기 | 평가자도 "추정". 브라우저 자동 테스트로 재현할 수 없어 실기기 근거가 생기면 반영 (실기기 확인 목록에 추가) |
| 선택 | 종단 검증 스크립트의 중복 정리 | 동작과 무관, 다음에 테스트를 크게 고칠 때 |
| 선택 | 재시도 상태 문구를 "서버 꺼짐" 대신 중립적으로 | 기반 설계의 상태 문구 목록을 바꾸는 일. 실기기 사용 뒤 판단 |
| 선택 | IP별 인증 대기 연결 제한 | 범위 확장 (설계에서 받아들인 위험) |
