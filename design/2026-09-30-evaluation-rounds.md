# 평가·보완 반복 기록

작성 2026-09-30 · 팀 눈길손길

얼굴 윤곽 기능까지 구현한 뒤, **평가 에이전트로 평가 → 보완점 반영 → 재검증**을 3번 반복했다. 각 버전에서 무엇이 달라졌는지 적는다.

- 평가 에이전트: 매 회차 같은 지시문 `design/eval/evaluator.md`를 쓰는 새 에이전트(이전 대화를 모름). 테스트·브라우저 종단 검증을 직접 실행하고 7개 기준(동작·안정성·보안·사생활·사용성·코드 품질·테스트·문서)을 1~5점으로 매기고 보완점을 필수/권장/선택으로 낸다.
- 반영 원칙: **필수는 모두**, 권장·선택은 효과를 따져 반영한다. 코드 변경은 실패하는 테스트를 먼저 만들고 통과시킨다. 반영하지 않은 항목은 이유를 남긴다.

## v1 → v2 (1회차 평가 반영)

### 평가 요약 (v1)
- 실행 점검: 서버 60·Node 25·종단 16단계 모두 통과, 스크린샷에서 뼈대·윤곽이 정확히 겹침. 직전 코드 검토 반영 6건 확인.
- 평가자가 **직접 재현한 결함 1건(필수)**: 실행 중 "카메라 전환"을 누르고 새 카메라가 열리기 전에 "정지"를 누르면, 정지 상태인데 카메라가 켜진 채 영상이 계속 나온다.

## v2 → v3 (2회차 평가 반영)

### 평가 요약 (v2)
- 실행 점검: 서버 60·Node 26·종단 17단계 모두 통과. 1회차 반영 13건이 모두 올바르게 반영됐다고 확인. 점수 변화 없음(내려간 기준 없음).
- 평가 시각을 바꿔(실제 폰 첫 사용, 오래 켜 두기, 인터넷 노출) 새 결함을 찾음. 4분 실행에서 이벤트 리스너·DOM 노드 증가 없음(누수 없음).
- 1회차에 미룬 "카메라 트랙 종료"를 평가자가 헤드리스 Chrome에서 **재현**(`track.stop()` + `ended` 이벤트): 화면은 검은데 "연결됨", 빈 프레임 계속 전송 → **필수로 격상.** 1회차의 "자동 테스트로 재현할 수 없다"는 판단이 틀렸다.

## v3 → v4 (3회차 평가 반영, 최종)

### 평가 요약 (v3)
- 실행 점검: 서버 60·Node 27·종단 20단계 모두 통과. 2회차 반영 10건이 모두 올바르게 반영됐다고 확인. **필수 없음.**
- 이번 시각: 처음 본 영역(서버 코드·실행 스크립트·README만 보고 설치), 2회차 수정의 회귀, 심사·시연 위험. 평가자가 타이머 20배속·가짜 Wake Lock으로 추가 재현.
- 점수: 사용성 3 → 4 (원인별 안내·16px·멈춤 안내·가로 배치). 문서 4 → 3 — 회귀가 아니라 처음 본 영역(README만으로 설치, 공개 페이지가 옛 버전)에서 빈틈이 나옴.
- 2회차에 "헤드리스라 검증 불가"로 미룬 Wake Lock 경쟁을 평가자가 **가짜 Wake Lock으로 재현** — 1회차의 카메라 종료와 같은 유형의 판단 착오. 이번에 반영.

## 세 번의 반복으로 무엇이 달라졌나

| | v1 | v4 |
|---|---|---|
| 자동 검증 | 서버 60 · Node 25 · 종단 16 | 서버 61 · Node 27 · 종단 24 + 기록 2 |
| 평가자가 찾은 결함 | 카메라가 꺼지지 않거나 끊긴 카메라로 "연결됨"을 보이는 경로 4개 (전환 직후 정지, 연결 중 종료, 시작 중 종료, Wake Lock 잔존) | 모두 수정, 각각 "수정을 빼면 실패"하는 테스트로 고정 |
| 폰 사용성 | 안내 부족 (거리, 오류 원인, 영어 코드), 아이폰 확대, 가로 화면 작음 | 원인별 한국어 안내, 16px, 토큰 보기, 가로 배치, 재시도 상한 |
| 사생활 | 주장은 맞지만 테스트·고지 부족 | 서버로 가는 메시지 모양을 종단에서 검증, 첫 화면(가로 포함) 전송 고지 |
| 운영 | README만으로 설치 불가, 공개 페이지가 옛 버전 | 설치 절차·시연 체크리스트, `run.ps1` 중복 실행 방지·한글 안내 |

**배운 것:** 세 번 모두 "자동 테스트로는 재현할 수 없다"며 미룬 항목을 다음 평가자가 가짜 객체(트랙 이벤트, Wake Lock, 타이머)로 재현했다. 브라우저 쪽 경쟁 상태는 대부분 헤드리스에서도 가짜 객체로 재현할 수 있으므로, "재현 불가"로 미루기 전에 먼저 흉내 내 볼 것.

**남은 것 (실기기):** 거리별 얼굴 인식과 물러났을 때 유지, 켬/끔에 따른 뼈대 fps·발열, 아이폰 Safari의 `wasm-unsafe-eval`·앱 전환 뒤 복구, 카메라 트랙 종료가 실제로 언제 일어나는지.
