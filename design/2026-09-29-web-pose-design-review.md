# 웹 카메라 자세 인식 시제품 설계 검토

작성 2026-09-29 · 대상 문서 `design/2026-09-29-web-pose-design.md`

## 1. 총평

구조는 그대로 진행해도 된다.

- 목적을 "인식 파이프라인이 실제 영상에서 동작하는지 확인"으로 좁혔고, 제외 범위가 분명하다.
- 원본 영상 전송이 계획서의 엣지 원칙과 다르다는 점을 문서에 밝혀 두었다.
- stop-and-wait 전송, 백엔드 `127.0.0.1` 바인딩, `secrets.compare_digest`, 0~1 비율 좌표는 적절한 선택이다.

아래는 구현 전에 정해 두어야 할 점이다. **2장은 반드시 반영**, 3~6장은 권장이다.

## 2. 반드시 반영할 것 (보안)

### 2.1 실제 방어선은 토큰 하나다
- Funnel 인증서는 인증서 투명성(CT) 로그에 공개되므로 `*.ts.net` 주소는 스캐너에 발견된다. "주소를 모르면 못 들어온다"는 가정은 성립하지 않는다.
- `Origin` 확인은 보안 수단이 아니다. 브라우저가 아닌 클라이언트는 헤더를 임의로 넣을 수 있다. 다른 웹사이트가 브라우저를 통해 접속하는 것을 막는 보조 수단으로만 본다.
- `Origin` 헤더가 **없는** 접속의 처리를 정한다.
  - 거부: `tools/stream_video.py`가 허용 목록의 Origin을 헤더로 넣어야 한다.
  - 허용: 브라우저 외 접속은 토큰만으로 막게 된다.
- 토큰은 `secrets.token_urlsafe(32)` 이상으로 생성한다고 명시한다. 시도 횟수 제한이 없으므로 토큰 길이가 곧 방어력이다.

### 2.2 FastAPI 기본 문서 페이지를 끈다
Funnel은 8000번 포트의 모든 경로를 공개하므로 `/docs`, `/redoc`, `/openapi.json`이 그대로 노출된다.

```python
app = FastAPI(docs_url=None, redoc_url=None, openapi_url=None)
```

`GET /health`는 `{"ok": true}`만 돌려주고 GPU·모델·버전 정보는 넣지 않는다.

### 2.3 동시 연결 수를 제한한다
"여러 명 동시 접속"을 범위에서 뺐지만 서버가 두 번째 연결을 거부한다는 규칙이 없다. 인증 전 연결도 5초씩 붙잡을 수 있어 GPU·메모리를 소모시킬 수 있다.

- 인증된 연결 최대 1개, 인증 대기 연결 최대 수 개
- 초과 시 새 코드(예: `4009`)로 닫는다

### 2.4 크기 제한은 두 단계로 건다
- uvicorn의 WebSocket 최대 메시지 크기 기본값은 16 MB다. 앱에서 1 MB를 확인하기 전에 16 MB까지 받는다. `--ws-max-size 1048576`으로 서버 단에서 막는다.
  - 이 경우 초과 시 연결이 끊긴다. 문서의 "`too_large` 후 연결 유지"와 충돌하므로 둘 중 하나로 정리한다. (권장: 서버 한도는 약간 여유 있게 두고, 1 MB 초과는 앱에서 `too_large`로 응답)
- **압축 폭탄**: 1 MB 미만 JPEG라도 헤더에 거대한 해상도를 적으면 디코딩 중 메모리가 폭증한다. 디코딩 전에 헤더로 크기를 읽고(PIL `Image.open(...).size`), 긴 변이 기준(예: 2000px)을 넘으면 `bad_image`로 거부한다.

### 2.5 `4001`·`4003`에서는 재연결하지 않는다
현재 규칙(3초 → 최대 10초 간격 재연결)대로면 틀린 토큰으로 계속 재시도한다. 이 두 코드는 재연결 없이 상태만 표시하고, 사용자가 설정을 고친 뒤 다시 시작하게 한다.

## 3. 권장 (보안·운영)

- **Funnel은 쓸 때만 켠다.** "한 번 켜 두면 유지된다"는 곧 상시 공개라는 뜻이다. 시험이 끝나면 `tailscale funnel --bg off`(또는 `tailscale funnel reset`)로 끄는 절차를 8장 "사용자가 직접 할 일"에 넣는다.
- **GitHub Pages 출처 공유**: `https://lumos0107.github.io`는 그 계정의 모든 Pages 저장소가 공유하는 출처다. Origin에는 경로가 없어 허용 목록을 이 저장소로 좁힐 수 없고, localStorage의 토큰도 같은 계정의 다른 Pages 프로젝트에서 읽을 수 있다. 본인 계정이라 위험은 낮지만 문서에 적어 둔다.
- **토큰 교체**: 유출이 의심되면 `server/.env`의 `TOKEN`을 바꾸고 서버를 재시작한다고 적어 둔다.
- **로그**: ultralytics는 `verbose=False`, `save=False`로 호출한다. uvicorn 접속 로그 수준도 정한다.
- **촬영 동의**: 팀원·시험 참가자를 촬영하기 전에 동의를 받는다는 점을 명시한다.

## 4. 통신 규격 보완

- 정의되지 않은 경우의 처리를 정한다.
  - 인증 전에 바이너리가 온 경우 (권장: `4001`로 닫기)
  - 인증 후 알 수 없는 텍스트 메시지 (권장: `{"type":"error","code":"bad_message"}`, 연결 유지)
  - 인증 후 auth 메시지가 다시 온 경우
- 다음 단계(넘어짐 판단)를 위해 응답에 필드를 미리 넣는다.
  - `img_w`, `img_h`: 비율 좌표만으로는 가로세로 비율이 사라져 몸통 기울기 같은 각도를 바로 계산할 수 없다.
  - `seq` 또는 촬영 시각: 시계열 분석과 응답 대조에 쓴다. 클라이언트가 보내고 서버가 그대로 돌려준다.

## 5. 프런트 구현 주의점

- **오버레이 지연**: 뼈대는 (왕복 시간 + 추론 시간)만큼 지난 프레임의 결과다. 영상은 실시간이라 움직이면 뼈대가 밀려 보이고, 인식이 부정확하다고 오해할 수 있다. 이 점을 명시하거나, 보낸 프레임을 멈춘 화면으로 함께 보여 주는 옵션을 둔다.
- **전면 카메라 반전**: `video`를 CSS로 좌우 반전하면 캔버스 좌표도 같이 반전해야 한다.
- **`object-fit: cover` 잘림**: 표시 영역에서 영상이 잘리면 비율 좌표를 그대로 그릴 때 어긋난다. 영상 → 캔버스 좌표 변환 방식을 정한다.
- 탭이 가려지면(`visibilitychange`) 전송을 멈춘다.
- 긴 시험 중 화면이 꺼지지 않도록 Screen Wake Lock을 쓴다.
- 키포인트 표시 기준 신뢰도(예: 0.5)를 정한다.
- JPEG 품질(예: 0.7)을 정한다.

## 6. 테스트 보완

추가할 자동 테스트
- 5초 안에 인증하지 않으면 `4008`
- 1 MB 초과 → `too_large`
- 인증 전 바이너리 전송
- 동시 연결 초과 시 거부
- `Origin` 헤더 없음 (2.1에서 정한 규칙대로)
- 헤더상 해상도가 과도한 JPEG → `bad_image`
- `/docs`, `/openapi.json` → 404

환경 관련 명시
- `bus.jpg`는 `.gitignore`의 `*.jpg`에 걸린다. 저장소에 넣지 않고 `ultralytics.utils.ASSETS / "bus.jpg"`를 쓴다.
- 가중치(`*.pt`)도 무시 대상이므로 첫 실행 때 자동으로 내려받는다고 적는다.
- 모델 입력 크기(`imgsz=640`)를 적어 결과를 재현할 수 있게 한다.

## 7. 사소한 것

- 파일 구조의 `tools/webcam_pose.py`는 현재 저장소 루트에 있다. 옮길 예정이면 그대로 둔다.

- [ ] `/docs`·`/redoc`·`/openapi.json` 비활성화, `/health` 최소 응답
- [ ] 동시 연결 제한과 종료 코드
- [ ] `--ws-max-size` 설정과 `too_large` 동작 정리
- [ ] 디코딩 전 이미지 해상도 확인
- [ ] `4001`·`4003`에서 재연결 금지
- [ ] Funnel 끄는 절차
- [ ] 정의되지 않은 메시지 처리 규칙
- [ ] 응답에 `img_w`·`img_h`·`seq` 추가
