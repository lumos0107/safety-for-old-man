장 번호는 1차 검토(1~7장)에 이어 8장부터 쓴다. "1차 검토 2.1"은 1차 검토 문서의 2.1을 가리킨다.

## 8. 총평

브라우저 계산을 택한 것은 타당하다.

- 서버와 통신 규격을 건드리지 않아 기존 60개 테스트와 검증된 연결 처리가 그대로 남는다.
- `mediapipe`와 OpenCV의 의존성 충돌이 통째로 사라진다.
- "얼굴 정보는 서버에서 계산하지 않는다"로 사생활 설명이 더 분명해진다.
- CDN 대신 저장소에 파일을 두고 출처·SHA-256을 기록한 것, 처음 켤 때만 불러오기, 기본 끔, 좌표를 자르지 않기는 모두 좋은 선택이다.

다만 **1차 검토 2.1의 전제가 틀렸고, 개정판이 그 전제를 근거 하나로 삼았다.** 이 정정(9.1)과 CSP(9.2), 메인 스레드 부담(9.3)을 반영하면 구현에 들어가도 된다. 10~11장은 구현하면서 반영해도 된다.

## 9. 반드시 반영할 것

### 9.1 [정정] 탐지 거리는 해상도가 아니라 화면 속 얼굴 크기 비율로 정해진다
- 1차 검토 2.1은 "640으로 줄여 보내서 얼굴이 작아진다"고 적었다. **원인을 잘못 짚었다.** Face Landmarker의 얼굴 탐지기는 원본 해상도와 상관없이 **프레임 전체를 128×128로 줄여** 본다. 얼굴이 프레임 폭의 5%면 1280이든 640이든 탐지기 입력에서는 약 6px로 같다.
- 원본 해상도가 주는 이득은 **윤곽의 정밀도**다. 탐지된 얼굴을 원본에서 잘라 랜드마크 모델에 넣으므로 윤곽 떨림이 줄어든다. 탐지 거리는 거의 늘지 않는다.
- 따라서 고칠 것:
  - 설계 3장 비교표의 "해상도" 행 → "원본 해상도로 윤곽이 더 정밀함. 탐지 거리는 같음 (화면 속 얼굴 비율로 정해짐)".
  - `개발_경위와_결정_기록.md` 6장의 "더 먼 거리의 얼굴을 잡을 수 있고" → 같은 취지로 고친다.
  - 브라우저 계산을 택할 이유는 표의 나머지 행(서버 무변경, 의존성 충돌 없음, 얼굴 정보가 서버로 가지 않음)만으로 충분하다.
- 7장 테스트의 "긴 변 640으로 줄인 영상"은 얼굴 비율이 그대로라 **탐지 거리를 시험하지 못한다.** 대신 사진을 1/2·1/3 크기로 줄여 1280×720 검은 바탕 가운데에 둔 영상으로 "멀리 있는 얼굴"을 흉내 내고, 어느 크기까지 잡히는지 기록한다.
- 실측 항목을 하나 더한다. VIDEO 모드는 한 번 얼굴을 잡으면 다음 프레임부터 이전 윤곽 주변만 따라가므로 탐지기를 매번 돌리지 않는다. **가까이서 잡은 뒤 뒤로 물러났을 때** 어디까지 유지되는지 재 본다. 시연 방법(가까이서 켜고 물러나기)으로 쓸 수 있다.
- 거리가 더 필요하면 서버가 준 머리 5점으로 영상 일부를 잘라 넣는 방법이 있다. 코드가 꽤 늘어나므로 이번 범위에서는 빼는 것을 권한다.

### 9.2 CSP: `connect-src`에 `'self'`가 없어 파일을 못 불러온다
- 지금 `index.html`의 CSP는 `connect-src wss: ws://localhost:* ws://127.0.0.1:*`다. `connect-src`를 따로 정하면 `default-src 'self'`는 fetch에 적용되지 않는다.
- MediaPipe는 `.wasm`과 `.task`를 **fetch로** 받는다. 설계 4장처럼 `script-src`만 더하면 같은 주소의 파일인데도 막힌다.
- 반영:
  ```
  default-src 'self'; script-src 'self' 'wasm-unsafe-eval';
  connect-src 'self' wss: ws://localhost:* ws://127.0.0.1:*; img-src 'self' blob:; media-src 'self' blob:
  ```
- 7장의 "CSP 위반 없음" 확인은 지금 종단 테스트(`tools/e2e_browser.py`)로는 안 된다. 테스트는 `pageerror`만 모으는데, CSP 위반은 여기로 오지 않는다. 페이지의 `securitypolicyviolation` 이벤트나 콘솔 오류를 따로 모아야 한다.
- 아이폰 Safari가 `'wasm-unsafe-eval'`을 받아들이는지는 실제 기기로 확인한다 (7장 수동 항목에 추가).

### 9.3 얼굴 계산이 화면의 메인 스레드를 막는다
- `detectForVideo`는 **동기 함수**다. 결과를 바로 돌려주고, 도는 동안 같은 스레드의 일(프레임 캡처·JPEG 만들기·WebSocket 처리·그리기)이 모두 기다린다.
  - 설계 5장의 "이전 계산이 끝나지 않았으면 그 프레임은 건너뛴다"는 이런 구조에서는 일어나지 않는다.
  - 비교표의 "얼굴 실패가 뼈대에 주는 영향 없음"도 속도에는 맞지 않는다. 느린 폰에서는 **뼈대 fps도 함께 떨어진다.**
- `requestAnimationFrame`은 화면 주사율(60~120Hz)로 돌고 카메라는 보통 30fps라, 같은 영상 프레임을 2~4번 계산하게 된다.
- 반영:
  - **새 영상 프레임일 때만** 계산한다. `video.requestVideoFrameCallback`을 쓰고, 지원하지 않으면 `video.currentTime`이 바뀌었는지 본다.
  - 초당 계산 횟수에 **상한**(예: 15회)을 둔다. 표시용이라 이 정도면 충분하다.
  - 7장 수동 항목 "켬/끔 fps 비교"를 **뼈대 fps**(서버 왕복) 비교로 명시한다.
  - Web Worker로 옮기면 확실히 분리되지만 구조가 복잡해진다. 실측에서 뼈대 fps가 크게 떨어질 때만 검토한다.

## 10. 권장

### 10.1 뼈대 결과가 없어도 윤곽을 그린다
- 지금 `draw()`는 `state.lastResult`가 없으면 바로 끝나고, 연결이 끊기면 `clearOverlay()`가 결과를 지운다. 그대로 얹으면 실시간 표시의 윤곽이 **서버 연결에 묶인다.** 연결 전, 재연결 중에는 얼굴이 안 나온다.
- `draw()`를 "지우기 → (동기면 보낸 프레임) → 뼈대(있으면) → 윤곽(있으면)" 순서로 바꾸고, 얼굴 계산이 끝날 때도 `draw()`를 부른다.

### 10.2 동기 표시: 원본 프레임은 보낼 때 잡고, 얼굴은 응답을 기다리는 동안 계산한다
- 지금 동기 표시용 프레임(`shown`)은 `onResult`에서 640 캡처를 복사한다. 원본 해상도 프레임을 이때 영상에서 새로 잡으면 **보낸 순간과 다른 장면**이 된다.
- `pump()`에서 영상을 원본 크기 캔버스에 한 번 그리고, 거기서 640 캡처를 만든다. 두 프레임이 같은 순간이 된다.
- 얼굴 계산은 프레임을 보낸 직후, 서버 응답을 기다리는 동안 하고 `seq`와 함께 보관한다. 응답이 오면 둘을 같이 그린다. 응답이 온 뒤에 계산하면 그만큼 표시가 더 늦는다.
- 동기 표시에서는 서버가 끊기면 윤곽도 멈춘다. 의도된 동작이라고 5장에 적는다.
- VIDEO 모드는 시간값(timestamp)이 계속 늘어나야 한다. 두 표시 방식 모두 `performance.now()` 하나로 넣는다.

### 10.3 켜기/끄기 경쟁과 불러오기 시간 제한
- 이전 최종 검토에서 나온 "시작을 두 번 누르면 카메라가 샌다"와 같은 종류의 문제다. 켜기·끄기를 빠르게 반복하면 모델이 두 번 만들어지거나, 끈 뒤에 불러오기가 끝나 계산이 시작될 수 있다.
  - 불러오기 약속(promise)을 하나만 두고, `cameraRequest`처럼 요청 번호로 마지막 요청만 살린다.
- LTE에서 16MB를 받는 데 시간이 걸린다. **시간 제한**(예: 30초)을 두지 않으면 "얼굴 모델 불러오는 중"에 계속 머무를 수 있다.
- 끌 때 `close()`로 GPU 메모리를 풀지 정한다. 파일은 브라우저 캐시에 남으므로 다시 켤 때 부담이 작다.

### 10.4 GPU 실패와 복귀
- "GPU를 먼저 시도하고 안 되면 CPU"의 흐름을 적는다. `createFromOptions`가 GPU로 실패하면 CPU로 다시 만든다.
- 아이폰은 다른 앱에 갔다 오면 WebGL 컨텍스트를 잃을 수 있다. 그러면 계산이 예외를 내고, 지금 설계대로면 얼굴 기능이 꺼진 채 남는다. **한 번은 다시 만들어 보고** 또 실패하면 끈다. `개발_경위와_결정_기록.md` 7장의 아이폰 복귀 확인에 이 항목을 더한다.

### 10.5 SIMD 판만 넣을 때의 경로
비SIMD 파일이 없으므로, 라이브러리가 자동으로 비SIMD 경로를 고르면 404가 난다. 불러오기 전에 SIMD 지원을 직접 확인하고(`FilesetResolver.isSimdSupported()`), 파일 경로는 SIMD 판으로 고정한다. 지원하지 않으면 불러오지 않고 "이 브라우저에서 쓸 수 없음"을 띄운다.

### 10.6 재배포 라이선스
- Apache-2.0은 재배포할 때 라이선스 사본을 함께 두어야 한다. `vendor/mediapipe/LICENSE`를 넣고 `SOURCE.md`에서 가리킨다.
- `.gitattributes`에 `vendor/** linguist-vendored`를 넣으면 GitHub 언어 통계가 내려받은 JS로 뒤덮이지 않는다 (사소).

## 11. 사소한 것

- `faceOutline(landmarks, rect)`: MediaPipe 결과는 `{x, y, z}` 객체의 배열이다. 테스트 입력도 그 모양으로 만든다.
- `index.html`에 `#faces`를 더하고 `resetStats()`에서도 `-`로 되돌린다.
- 헤드리스 Chrome에서는 GPU(WebGL)가 안 돼 CPU 경로로 돌 가능성이 크다. 자동 테스트는 CPU 경로를 확인하는 것으로 보고, GPU 경로는 폰 수동 시험에서 확인한다고 적는다.
