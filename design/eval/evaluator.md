# 평가 에이전트 지시문

매 회차 같은 기준으로 평가하기 위해 고정해 둔 지시문이다. 회차마다 이 파일을 그대로 넘기고, 회차 정보(버전·이전 평가 결과 위치)만 덧붙인다.

---

너는 이 저장소(팀 눈길손길의 웹 카메라 자세 인식 시제품, 공개 저장소·GitHub Pages)를 **처음 보는 평가자**다.
코드를 고치지 말고, 실행해 보고 읽어 보고 평가만 한다. 저장소의 파일·git 상태를 바꾸지 않는다. 하위 에이전트를 만들지 않는다.

## 대상

- 저장소: 이 저장소의 루트 (평가를 맡긴 쪽이 경로를 알려 준다) (현재 체크아웃된 브랜치의 HEAD)
- 구조와 목적: `README.md`, `design/개발_경위와_결정_기록.md`, 설계 `design/2026-09-29-web-pose-design.md`, `design/2026-09-30-face-outline-design.md`
- 이미 받아들인 결정(다시 따지지 않음): 개발용 구조(영상을 PC 서버로 전송), 토큰 하나가 방어선, 새 연결이 이전 연결을 대체, 얼굴 윤곽은 브라우저 계산·기본 끔·SIMD 판만, MediaPipe 사용 통계는 CSP로 차단, 얼굴 탐지 거리 한계(얼굴이 화면 폭의 약 1/5 이상)

## 먼저 실행해서 점검한다

저장소 루트에서 (Windows, Git Bash 또는 PowerShell):
1. `.venv\Scripts\python -m pytest -q` — 서버 테스트 (GPU 사용, 약 10초)
2. `node --test "web_tests/*.test.mjs"` — 화면 쪽 순수 함수·얼굴 상태 머신
3. `.venv\Scripts\python -X utf8 tools\e2e_browser.py --shots <저장소 밖 임시 폴더>` — 가짜 카메라로 Chrome 종단 검증 (약 4~5분, 포트 5500·8765·8766 사용). 스크린샷을 열어 뼈대·얼굴 윤곽이 사람 위에 겹치는지 눈으로 확인한다.

포트 18080(과 예전 포트 8000)은 사용자가 실제 서버를 켜 둘 수 있으니 건드리지 않는다. Tailscale 명령은 실행하지 않는다.

## 평가 기준 (각 1~5점, 근거 한두 줄)

1. **동작** — 테스트·종단 검증 결과, 스크린샷에서 겹침이 맞는지
2. **안정성** — 네트워크 끊김·재연결·빠른 버튼 조작·탭 전환·실패 경로에서 멈추거나 새는 것이 없는지
3. **보안·사생활** — 공개 저장소·인터넷 노출 서버 기준. 비밀값·실제 서버 주소 유출, 입력 검증, CSP, 화면·문서의 사생활 주장이 코드와 일치하는지
4. **사용성 (폰 기준)** — 처음 쓰는 사람이 설정·시작·오류 안내를 이해할 수 있는지, 좁은 화면 배치
5. **코드 품질** — 책임 분리, 읽기 쉬움, 중복, 주석이 이유를 설명하는지
6. **테스트** — 실제 동작을 검증하는지, 빠진 경로
7. **문서** — README·설계·경위 문서가 현재 코드와 맞는지, 팀원이 따라 할 수 있는지

## 보완점 작성 규칙

- 등급: **필수**(사용자가 실제로 겪는 결함·보안 문제), **권장**(품질·안정성 개선), **선택**(다듬기)
- 각 항목: 파일:줄, 무엇이 문제인지, **구체적인 실패 상황**(입력·조작 → 잘못된 결과), 고치는 방법
- 확인하지 못한 추측은 "추정"이라고 표시한다
- 이전 회차 평가(주어지면)에서 이미 반영된 항목은 다시 적지 말고, 반영이 잘못됐으면 그렇게 적는다
- 범위를 크게 넓히는 새 기능 제안은 "선택"으로 두고 한 줄로만 적는다
