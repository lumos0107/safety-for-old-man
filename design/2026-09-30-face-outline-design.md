# 얼굴 윤곽 표시 설계 (브라우저 계산)

작성 2026-09-30 · 팀 눈길손길 · 기반 설계 `design/2026-09-29-web-pose-design.md` (이 문서는 그 위에 얹는 추가 기능)
개정 2026-09-30 · `2026-09-30-face-outline-design-review.md` 반영 — 서버 계산에서 **브라우저 계산**으로 바꿈 (끝의 "검토 반영 기록" 참고)

## 1. 목적

폰·노트북 화면에서 사람의 뼈대에 더해 **얼굴 윤곽(턱선·이마 둘레)**을 그린다.

**왜 필요한가:** 시연할 때 인식이 사람에게 제대로 붙어 있는지 한눈에 보여 주기 위한 **표시 기능**이다.
넘어짐·휘청임 판단에는 쓰지 않는다. 판단에 필요한 머리 위치는 자세 모델의 코·눈·귀 5점으로 충분하다.

자세 모델(YOLO11n-pose)은 얼굴에서 5점만 주므로 윤곽을 만들 수 없다. 얼굴 전용 랜드마크 모델이 필요하다.

## 2. 범위

포함
- 브라우저에서 얼굴 랜드마크 모델 실행, 윤곽 36점 그리기
- 설정의 켜기/끄기 (기본 끔), 얼굴 수 표시

제외
- 서버·통신 규격 변경 — **없음.** 서버는 얼굴을 계산하지 않고 얼굴 정보를 받지도 않는다.
- 눈·눈썹·입 모양, 표정·통증 판단, 고개 방향 계산
- 얼굴로 사람을 식별하는 모든 기능
- 얼굴과 사람(뼈대)을 짝짓기 — 화면에 따로 그리기만 한다

## 3. 왜 브라우저에서 계산하나

| | 서버 계산 (처음 설계) | 브라우저 계산 (선택) |
|---|---|---|
| 해상도 | 서버가 받는 640 프레임 → 1m 안쪽에서만 잡힐 가능성 | **카메라 원본(최대 1280×720)**으로 계산 |
| 얼굴 실패가 뼈대에 주는 영향 | 따로 처리 필요 | 서버와 별개라 없음 |
| 모델 내려받기 안전성 | 실행 중 내려받기·해시 확인 필요 | 저장소에 함께 두어 git이 무결성 보장, 실행 중 외부 내려받기 없음 |
| 서버 지연 | 늘어남 | 없음. 윤곽이 영상에 바로 따라붙음 |
| 설치 | `mediapipe`와 OpenCV 충돌 해결 필요 | 서버 변경 없음 |
| 사생활 설명 | 서버가 얼굴 좌표를 계산 | "얼굴 정보는 서버에서 계산하지 않는다" |
| 부담 | PC | 카메라 기기(폰·노트북). 오래된 폰은 느리거나 뜨거워질 수 있음 |

노트북을 카메라로 쓰는 경우도 브라우저 계산이 맞다. 이 모델은 폰에서 실시간으로 돌리도록 만든 가벼운 모델이라 노트북은 GPU 없이도 충분하다. 노트북을 서버로 쓰는 경우에는 GPU가 없어 서버 부담을 줄이는 쪽이 더 중요하다.

## 4. 모델과 파일

- **MediaPipe Face Landmarker** (웹용 `@mediapipe/tasks-vision` 1.0.1, Apache-2.0). 얼굴당 478점 중 **윤곽(face oval) 36점만** 쓴다.
- 윤곽 36점의 순서 (MediaPipe 얼굴 메시 번호, 이 순서로 이으면 닫힌 윤곽선):
  `10, 338, 297, 332, 284, 251, 389, 356, 454, 323, 361, 288, 397, 365, 379, 378, 400, 377, 152, 148, 176, 149, 150, 136, 172, 58, 132, 93, 234, 127, 162, 21, 54, 103, 67, 109`
- 설정: 얼굴 최대 3개, 탐지 신뢰도 0.5, 실행 모드 VIDEO, `outputFaceBlendshapes: false`, `outputFacialTransformationMatrixes: false` (표정·머리 자세는 계산하지 않음). 가속은 GPU(WebGL)를 먼저 시도하고 안 되면 CPU.
- **파일을 저장소에 함께 둔다** (`vendor/mediapipe/`, Pages가 같은 주소에서 제공). CDN에서 실행 중에 받지 않는다 — 외부 서버 의존과 공급망 위험을 없애고, 파일 무결성은 git 기록이 보장한다.
  - `vision_bundle.mjs` (155KB)
  - `wasm/vision_wasm_internal.js`, `wasm/vision_wasm_internal.wasm` (12MB, WebAssembly SIMD 판)
  - `face_landmarker.task` (약 4MB, float16 모델)
  - 비SIMD 판(11MB)은 넣지 않는다. SIMD를 지원하지 않는 오래된 브라우저(iOS 16.4 미만 등)에서는 얼굴 윤곽만 "이 브라우저에서 쓸 수 없음"으로 표시하고 뼈대는 그대로 동작한다.
  - 파일의 출처(npm 패키지 주소·버전, 모델 주소)와 SHA-256을 `vendor/mediapipe/SOURCE.md`에 적어 누가 받아도 같은 파일인지 확인할 수 있게 한다.
- **보안 정책(CSP)**: WebAssembly 실행을 위해 `script-src 'self' 'wasm-unsafe-eval'`을 더한다. 외부 주소는 여전히 허용하지 않는다. 구현 중 추가 완화가 필요하면 이 문서에 이유와 함께 적는다.
- 모델은 **얼굴 윤곽을 처음 켤 때만** 불러온다. 끈 상태로 쓰는 사람은 12MB를 내려받지 않는다.

## 5. 화면 동작

- 설정 창에 체크박스 **"얼굴 윤곽 표시 (시연용)"**. **기본은 끔.** `localStorage` 키 `pose.face`.
- 켜면 모델을 불러오고(첫 한 번, "얼굴 모델 불러오는 중" 안내), 이후 계산한다. 불러오기에 실패하면 안내문을 띄우고 얼굴 기능만 끈다.
- 계산 대상은 표시 방식을 따른다. 뼈대와 같은 프레임에 겹쳐야 하기 때문이다.
  - **실시간 표시**: 화면의 카메라 영상(원본 해상도)을 `requestAnimationFrame`마다 계산한다. 이전 계산이 끝나지 않았으면 그 프레임은 건너뛴다. 윤곽은 영상에 바로 따라붙는다 (뼈대는 서버 왕복만큼 늦는다는 기존 안내 유지).
  - **동기 표시**: 서버에 보낸 프레임을 결과와 함께 보관할 때 원본 해상도로도 보관하고, 그 프레임으로 계산한다. 뼈대와 윤곽이 같은 순간을 가리킨다.
- 상단 표시줄에 **얼굴 수** (`#faces`). 꺼져 있으면 `-`.
- 그리기: 얼굴마다 36점을 이은 **분홍(`COLORS.face`) 닫힌 선**, 두께 2px. 뼈대 다음에 그린다. 좌우 반전·레터박스는 뼈대와 같은 좌표 변환(`fitContain`)을 쓴다. 좌표를 0~1로 자르지 않는다 (화면 밖은 캔버스가 알아서 잘라 윤곽이 납작해지지 않음).
- 탭이 가려지면 계산을 멈추고, 돌아오면 다시 한다 (기존 전송 규칙과 같음).
- `lib.js`에 `faceOutline(landmarks, rect) -> [[x, y], …]` (478점 중 윤곽 36점을 순서대로 뽑아 화면 좌표로) 순수 함수를 두고 테스트한다.

## 6. 사생활

- 얼굴 윤곽 좌표는 사람을 알아보는 데 쓰일 수 있는 정보에 가깝다.
- **기기 안에서만 계산하고, 서버로 보내지 않으며, 저장하지 않는다.** 478점 중 36점만 쓰고 나머지는 바로 버린다.
- 기본은 꺼 두고 시연할 때만 켠다.
- 넘어짐 판단 등 이후 기능은 얼굴 윤곽을 입력으로 쓰지 않는다. 심사·발표에서는 "시연용 표시 기능"으로만 소개한다.
- (참고) 영상 자체는 기존 개발용 구조대로 서버로 전송된다. 이 기능이 그 사실을 바꾸지는 않는다.

## 7. 테스트

자동
- Node: `faceOutline` — 478점 입력에서 36점을 정해진 순서로 뽑는지, 화면 좌표 변환, 점이 모자라면 빈 배열.
- 브라우저 종단 (기존 8단계 유지, 단계 추가)
  - 기본 끔: `#faces`가 `-`이고 모델 파일을 요청하지 않음
  - 가짜 카메라를 `zidane.jpg`(가까이 찍힌 2명, 1280×720)로 한 브라우저를 따로 띄워 켬 → `#faces` 1 이상, 스크린샷으로 윤곽이 얼굴에 겹치는지 확인
  - 같은 사진을 **긴 변 640으로 줄인 영상**으로도 확인 (검토 2.1: 작은 얼굴에서 잡히는지 기록)
  - 페이지 오류·CSP 위반 없음
  - 동기 표시에서도 윤곽이 그려짐

수동 (폰·노트북, 사용자)
- **거리별 인식 여부**: 0.5 / 1 / 2m에서 윤곽이 나오는지 실측해 README에 적는다.
- 폰 발열·fps: 얼굴 윤곽 켬/끔에서 fps 비교.

## 8. 반영 절차

- 구현·테스트 후 `main`에 push한다 (Pages 반영 1~2분). **서버는 다시 시작할 필요 없다.**
- 기반 설계 문서 6장(프런트)에 이 기능을 한 줄로 요약해 둔다.

| 검토 항목 | 반영 |

| 2.2 얼굴 실패가 뼈대를 막음 | 서버와 분리되어 해당 없음. 브라우저에서 불러오기·계산 실패는 얼굴 기능만 끔 |
| 2.3 내려받기 안전 | 실행 중 내려받기를 없애고 저장소에 포함, 출처·SHA-256 기록 (4장) |

| 4 기본값 끔·목적 명시 | 반영 (1장, 5장, 6장) |

검토에 없던 것:
- 모델은 얼굴 윤곽을 처음 켤 때만 불러온다 (끈 사람은 12MB를 받지 않음).
- 비SIMD 판을 빼 저장소 크기를 줄이고, 지원하지 않는 브라우저에서는 얼굴 기능만 쓸 수 없다고 안내한다.
- CSP에 `'wasm-unsafe-eval'`이 필요하다.
